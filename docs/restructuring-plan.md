## 如何查看进度

- 先看“当前快照”和“最近三批”，再按 P0–P9 查看阶段。

- 状态使用：未开始、进行中、代码完成待验收、已验收。技术完成必须有检查证据；界面与三端运行必须有实际运行证据。

## 0 到 1 的终点

一个新玩家能够从启动、登录、创角/角色初始化进入主城，获得英雄、出阵、挑战主线、播放战报、领取结算、挂机领取和基础养成；退出重登数据一致。三端至少各有可安装/运行的验收包。收费发行还必须通过 P8/P9，不能把开发联调版本称为上线完成。

首测范围：账号与角色、主城、英雄、背包、阵容、主线战斗、结算、挂机、基础召唤与养成、基础邮件。公会、跨服及复杂活动放到闭环稳定之后。旧项目中存在的系统不自动进入首测范围。

## P2 资源管理与加载（当前重点）

前置：P0；复用 P1 的加载展示。目标：统一依赖、加载、持有、取消与释放，尽早验证包体和内存。

- P2-02【代码完成待验收】集中登记四项启动资源的 ID、路径和类型，接回真实启动任务；不再在 RemakeApp 内散写资源地址。输出 StartupResources.ts。
- P2-03【代码完成待验收】共享请求去重、资源作用域、失败重试、关闭后拒绝迟到结果、最后持有方退出后撤销引用。输出 ResourcePool.ts 与 resources 检查。
- P2-04【进行中】主城入口已移入 remake-home Bundle，保留 UUID 并移除场景直引，成功点击开始后才加载；静态闭包缩小已核对，实际 Bundle 导入/构建/传输和三端样包尚未验收，不能据此宣称包体优化完成。
- P2-05【进行中】重做版已改为登录前两张表、主城另五份；独立分组缓存不覆盖旧 ConfigDb，旧 loadAll 保留。原子提交、失败重试与真实文件检查通过；英雄/战斗依赖、投影绑定与实际运行待继续核对，见 [配置分组说明](config-loading.md)。
- P2-06【未开始】逐步把已有页面迁到作用域加载，覆盖 UIManager 打开、取消、关闭、缓存与重开；保持 Prefab 可编辑及 UUID 稳定。
- P2-07【未开始】主动释放与预算：先清点旧加载器、Spine 副本、材质、音频、字体和纹理的持有方，再启用缓存淘汰；测首屏、峰值内存、反复进出后的趋势及重开耗时。
- P2-08【未开始】三端资源版本、缓存失效、离线/超时/失败重试、远程资源与回滚小样；不加载两版混合资源，不把任务进度冒充下载字节进度。
- P2-09【未开始】资源美术规范：逻辑尺寸、像素倍率、裁切余量、九宫格、图集、命名、简体中文与交付格式；压缩方案以样包画质/耗时/内存测量决定。

当前限制：新作用域仅覆盖启动的四项公共资源。Cocos 适配器撤销自身引用时使用 decRef(false)，保留引擎缓存，避免释放仍被旧页面使用的资源；这不是主动内存回收完成。取消只取消接收，不承诺中止引擎底层下载。

阶段出口：有可复跑的资源依赖清单、能证明减少首屏依赖的构建样本、页面重开与失败恢复证据、不会释放其他持有方的检查，以及实际内存基线。源资源目录大小不能代替包体/首屏下载量。

## 每批工作的更新规则

1. 开始前读取本文、development-progress.md 和 Git 状态，选择依赖已满足的一小组任务。
