# H5 连本机游戏服 WebSocket（D2）

默认预览仍然是 Mock，不连 13101。要看真套接字时再加查询参数。D2 勾选仍等倩本机看过心跳和登录回包，这一轮不勾。

## 倩怎么开

1. 拉这份代码。
2. 双击 `scripts/start-local-server.bat`，确认本机 **13101** 在听（center **11122**、游戏服 TCP **9902** 一起起来即可）。这个 bat 在倩的机器上，不在 Git 里。
3. Creator 3.8.8 打开 `client`，启动场景保持 Boot，预览。
4. 浏览器打开：

`http://127.0.0.1:7456/?transport=ws`

安全区调试可以写在一起：`http://127.0.0.1:7456/?transport=ws&safe=88,0,34,0`。

5. 登录面板标题下应出现 `ws://127.0.0.1:13101`。打开成功时面板是「已打开，心跳 1004 已发送」，Toast 同这句。GameLog（主城日志，或控制台 `[mxzg]`）里有一行 `发送 c2s 1004 帧长 8 04000000ec030000 空体`。之后大约每 25 秒再发一次。
6. 账号填**数字平台 uid**（旧桥日志里见过 `111` 和 `960011`），点 **进入游戏**。GameLog 应有 `发送 c2s 1001`，随后 `收到 s2c …`（协议号、帧长、十六进制）。空回包表示日志里的「还没有角色」。点 **创角**，写名字，确认后发 `1002`，再发一次 `1001`。有角色时状态里会出现「角色 …」。两种都不进主城，也不把 Mock 金币写成服务器进度。
7. 刷新后再用同一个数字 uid 点进入游戏。若服务器留下了角色，回包字段 1 仍是那个角色 id。这是刷新之后还能对上真服的路径。若回包仍是空的、连接被关掉、或根本没有 `收到 s2c 1004`，把 GameLog 里这几行留住。
8. 服没开时面板是「服未启动，请检查启动 bat」。点 **改走 Mock** 仍进原来的 Mock 主城。
9. 去掉 `?transport=ws`，或改成 `?transport=mock`，全程 Mock。`skipLogin` 只跳过 Mock 面板；带了 `transport=ws` 仍显示这块面板。

换地址（一般不用）：`?transport=ws&ws=wss://127.0.0.1:13101`。本地分析里 SSL 证书是空的，默认用 **ws**，不要改成 wss。

代码开关在 `client/assets/scripts/net/transportSelect.ts` 的 `TransportConfig.defaultKind`，仓库里保持 `"mock"`。

## 帧格式（net-20261020 桥日志已证明）

旧 H5 的 `serve.ps1` 把 WebSocket `/game/9902` 桥到游戏服 TCP `9902`。`uploads` 里的 `net-20261020.jsonl` 是这条桥的原始字节。本仓库仍连分析里的直连口 `ws://127.0.0.1:13101`，不走那条桥。13101 是否同一套帧，日志证明不了；下面按桥上的 TCP 帧来组包。若 13101 不同，GameLog 里不会出现成对的 `s2c 1004`，或会记「帧长度异常」。

| 字节 | 含义 |
|------|------|
| 0–3 | uint32 小端。值 = cmdId + 包体的长度 = 整帧长度 − 4 |
| 4–7 | uint32 小端 cmdId |
| 8… | protobuf 包体，可以是空的 |

一条 WebSocket 二进制消息里可以粘着多帧（这份日志里有 35 条）。半帧会留到下一条再解。

心跳 c2s **1004** 整帧就是 8 字节：`04 00 00 00 ec 03 00 00`。包体是空的。同一条连接上，1606 个间隔的中位数是 **25.009 秒**（大约 1533 个落在 25.0 秒）。所以间隔用 25 秒，不是占位 NetClient 的 5 秒，也不是分析里 TCP 空闲的 60 秒。连上会先发一拍，然后每 25 秒一拍。s2c 1004 的包体是 protobuf，两例以外都很常见：字段 1 是一个大整数（毫秒时间）。s2c **1005** 也记下来，字段 1 见过 34501 和 60254，含义没有 .proto，不拿它当登录成功。

登录 c2s **1001**。两例包体字段号相同，uid 和时间不同：

| 字段 | 两例里的值 |
|------|------------|
| 1 varint | 都是 7 |
| 2 varint | 平台 uid：`111` 或 `960011` |
| 3 varint | 都是 2 |
| 5 string | 十进制 unix 秒：`1792464901` 或 `1792466798` |
| 6 string | `localdev` |
| 7 string | `mxzg-web-1001` |

账号不是正整数时，字段 2 不写，并在 GameLog 说明。没有去接平台 OAuth，也不自己编一个 uid。面板上的选服 id 不写入这包：两例的字段 1、字段 3 都不随选服变化。密码不下发。

s2c 1001 包体为空：日志里下一步才是创角。有包体时字段 1 是角色 id（例如 1000002），字段 2 是毫秒时间，字段 4 见过 28800。

创角 c2s **1002**（这是线上创角，不是占位表里的心跳 1002）：

| 字段 | 日志里的值 |
|------|------------|
| 1 string | 角色名。两例都是「见习冒险家」，这里用面板上写的名字 |
| 2 varint | 0 |
| 3 varint | 2 |
| 4 string | `local` |
| 5 string | `mxzg-web-1001` |

s2c 1002 字段 1 是新角色 id。日志里创角成功后会再发一次 1001。这里照做。再往后那一大串空包（2001、51001、11005…）是进游戏的同步，没有 .proto 名字，这一轮不发，也不把 Mock 钱包填进去。

占位 `CmdId.heartbeat` 仍是 **1002**，只给 Mock。线上心跳是 **1004**。不要把占位表改成 1004，否则和线上创角号撞在一起。

## 这一步做了什么

- `protocol/frame.ts` 编解码长度前缀帧，并切开粘包。
- `protocol/wireLogin.ts` 只编码上面能从日志对上的 1001 / 1002。
- `WsTransport` 在 `?transport=ws` 时发送这些帧，并把收到的协议号、帧长、十六进制写进 GameLog。
- 打开后发心跳。点「进入游戏」发 1001。点「创角」且 1001 回包为空时，才发 1002。
- 默认仍是 Mock。不进真实主城。

真实登录进主城仍是 D3。
