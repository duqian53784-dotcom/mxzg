# H5 连本机游戏服 WebSocket（D2 已验证，D3 主城壳）

默认预览仍然是 Mock。要看真套接字时再加 `?transport=ws`。那会去连本机桥 `ws://127.0.0.1:13111/game`，桥把二进制帧原样转到游戏服 TCP `9902`。

D2 已在倩本机勾过：`收到 s2c 1001`（例：角色 1000002），后面还有真服推送。不要直连 13101。

D3 仍未勾完。s2c 1001 里有角色 id 时，登录面板关掉，进入和 Mock 同一套顶栏、底栏。进主城后按旧桥日志先发一帧空的 c2s **2001**，紧接着再发一帧空的 c2s **3007**。s2c 2001 按 Role.proto 的 `GResRoleInfo` 写入顶栏：字段 9 昵称、字段 6 等级、字段 2 金币、字段 1 宝石（顶栏钻石）。某个字段没出现，那个格子仍是「未同步」。字段 5 是奖杯，不写成金币。s2c 3007 按 Battle.proto 的 `GResChapterData` 写主城「主线」按钮：字段 2 是当前 idx，字段 3 是最高 idx。某个 idx 没出现就不写成 0，两个都没有时按钮仍是「主线 · 未同步」。开服天仍是「未同步」。不把 Mock 的 100 / 20 或「第 N 关」当成服务器进度。空回包仍走创角。玩法页仍只 Toast，主线按钮也只 Toast，不打开 Mock 关卡页。

## 倩怎么开

1. 拉这份代码。
2. 双击一次 `scripts\start-local-all.bat`。它会另开窗口跑 `start-local-server.bat`，TCP **9902** 起来后再另开窗口跑 `start-ws-bridge.bat`。9902 已经在听就跳过游戏服，并写明不再启动第二个。13111 已经在听就跳过桥。center **11122**、游戏服自带 WS **13101** 仍由启服脚本负责。13101 在听只说明游戏服起来了，预览不要连它。
3. 桥窗口应出现 `[桥] 正在听 ws://127.0.0.1:13111/game`，以及 `TCP 127.0.0.1:9902 可以连接`。游戏服窗口和桥窗口都留着。只拉了客户端代码时，不必重启这两边，刷新预览即可。双击 `scripts\stop-local-all.bat` 只停桥，并打印游戏服怎么停；游戏服仍是在窗口里输入 stop，不结束别的进程。分拆时仍可单独双击 `start-local-server.bat` 和 `start-ws-bridge.bat`。
4. Creator 3.8.8 打开 `client`，启动场景保持 Boot，预览。不用改场景，也不用再挂组件。
5. 浏览器打开：

`http://127.0.0.1:7456/?transport=ws`

安全区调试可以写在一起：`http://127.0.0.1:7456/?transport=ws&safe=88,0,34,0`。

6. 登录面板标题下应出现 `ws://127.0.0.1:13111/game`。打开成功时面板是「已打开，心跳 1004 已发送」，Toast 同这句。GameLog（控制台 `[mxzg]`）里有一行 `发送 c2s 1004 帧长 8 04000000ec030000 空体`。桥窗口应有「已把浏览器的字节转到游戏服」。登录之前可以没有 `收到 s2c 1004`：本机对一条新的 TCP 9902 只发心跳，5 秒没有回包。
7. 账号填**数字平台 uid**（旧桥日志里见过 `111` 和 `960011`；倩本机已有角色 `1000002`），点 **进入游戏**。GameLog 应有 `发送 c2s 1001`，随后 `收到 s2c 1001`。字段 1 是角色 id 时，登录面板关掉，进入主城。接着应有 `发送 c2s 2001 帧长 8 04000000d1070000 空体`，然后 `收到 s2c 2001`，以及 `发送 c2s 3007 帧长 8 04000000bf0b0000 空体` 和 `收到 s2c 3007`。回包到达之前，顶栏左侧是「角色 id」或刚填的创角名，不显示占位 `Lv1`，右侧是「金币 未同步」「钻石 未同步」，中间按钮是「主线 · 未同步」。GameLog 出现 `角色名 … 等级 … 金币 … 钻石 …` 后，顶栏改成这四个数：名字和等级在左侧，金币和钻石在右侧。只写这一包里解开的字段。缺了的格子保持「未同步」。不要把字段 5 的奖杯当成金币，也不要写成 Mock 的金币 100、钻石 20。下面仍是「真服 · 角色 id」，不写开服 D。主城说明里开服天仍是未同步。底栏五个入口还在。`收到 s2c 3007` 之后，中间按钮改成这一包里的 idx：字段 2 写成「当前 N」，字段 3 写成「最高 M」。日志三例没有字段 2、字段 3 是 0，按钮是「主线 · 最高 0」。本机号若已经打过关，以这次回包为准，不要看成 Mock 的「第 1 关」。点主线、挂机、英雄、召唤等仍 Toast「真服这一页还没接，不会打开 Mock 页面」。2001 或 3007 解不开时，对应的顶栏或按钮保持上一次，预览不因此停下。
8. 空的 s2c 1001 表示还没有角色，停在登录面板。点 **创角**，写名字，确认后发 `1002`，再发一次 `1001`。第二次 1001 有角色 id 才进主城。顶栏先用刚填的名字，s2c 2001 到了再改成服上的名字、等级、金币和钻石。没有角色 id 不进，也不发 2001 和 3007。
9. 登录成功后马上会有一串真服推送（倩本机见过 28000、28103、20005、25001、23000、21013、50000 等）。GameLog 里是 `收到 s2c …`。这些包只记录，不写成金币或等级。预览不应因此停下。占位 `CmdId` 不改（Mock 的 `tower.view` 仍是 2001）。心跳仍是 **1004**。
10. 若 5 秒内没有对上的回包，面板是「登录 1001 请求超时」，下面一行是 `s2c=有/无 心跳1004回包=有/无 登录1001回包=有/无`。GameLog 里还有这句的说明，以及超时前最近 6 条 `Ws` 行（前缀 `超时前`）。没有任何 s2c 时，先看桥窗口是否还在，以及 9902 是否在听。
11. 刷新后再用同一个数字 uid 点进入游戏。若服务器留下了角色，回包字段 1 仍是那个角色 id，并再次进入主城壳。
12. 桥或游戏服没开时面板是「服未启动，请检查启动 bat」。点 **改走 Mock** 仍进原来的 Mock 主城，顶栏回到 Mock 的金币和钻石。
13. 去掉 `?transport=ws`，或改成 `?transport=mock`，全程 Mock。`skipLogin` 只跳过 Mock 面板；带了 `transport=ws` 仍显示这块面板。

换地址（一般不用）：`?transport=ws&ws=ws://127.0.0.1:13111/game`。不要改成 `ws://127.0.0.1:13101/` 或 wss。本地分析里 SSL 证书是空的。

代码开关在 `client/assets/scripts/net/transportSelect.ts` 的 `TransportConfig.defaultKind`，仓库里保持 `"mock"`。

## 为什么不直连 13101

2026-10-21 倩本机游戏服已在听：

| 探法 | 结果 |
|------|------|
| `ws://127.0.0.1:13101/` | HTTP 101，握手成功 |
| `/websocket`、`/ws`、`/game`、`/game/9902` | 握手读超时，没有 101 |
| 101 之后发送心跳帧 `04 00 00 00 ec 03 00 00` | 5 秒没有回包 |
| TCP `127.0.0.1:9902` 发送日志里的 c2s 1001（uid 111 那一帧） | 立刻回到 `13 00 00 00 e9 03 00 00 …`（s2c 1001，后面还有同步包） |
| 同一条新 TCP 只发心跳 | 5 秒没有回包 |

所以默认地址是桥，不是 13101。桥只做 WebSocket 帧和 TCP 字节的互相搬运，不改包体。路径只认 `/game` 和 `/game/`。别的路径回 404。9902 没听时回 502，浏览器看不到 101，面板走「服未启动」。

## 帧格式（net-20261020 桥日志已证明，TCP 9902 已复现）

旧 H5 的 `serve.ps1` 把 WebSocket `/game/9902` 桥到游戏服 TCP `9902`。`uploads` 里的 `net-20261020.jsonl` 是这条桥的原始字节。本仓库的 `scripts/start-ws-bridge.ps1` 做同样的事，只是听在 `13111/game`。下面按这些字节组包。

| 字节 | 含义 |
|------|------|
| 0–3 | uint32 小端。值 = cmdId + 包体的长度 = 整帧长度 − 4 |
| 4–7 | uint32 小端 cmdId |
| 8… | protobuf 包体，可以是空的 |

一条 WebSocket 二进制消息里可以粘着多帧（这份日志里有 35 条）。半帧会留到下一条再解。

心跳 c2s **1004** 整帧就是 8 字节：`04 00 00 00 ec 03 00 00`。包体是空的。同一条连接上，1606 个间隔的中位数是 **25.009 秒**（大约 1533 个落在 25.0 秒）。所以间隔用 25 秒，不是占位 NetClient 的 5 秒，也不是分析里 TCP 空闲的 60 秒。连上会先发一拍，然后每 25 秒一拍。s2c 1004 的包体是 protobuf，两例以外都很常见：字段 1 是一个大整数（毫秒时间）。s2c **1005** 也记下来，字段 1 见过 34501 和 60254，含义没有 .proto，不拿它当登录成功。

登录 c2s **1001**。两例包体字段号相同，uid 和时间不同：

| 字段 | 两例里的值 |
|------|------------|
| 1 varint | 都是 7 |
| 2 varint | 平台 uid：`111` 或 `960011` |
| 3 varint | 都是 2 |
| 5 string | 十进制 unix 秒：`1792464901` 或 `1792466798` |
| 6 string | `localdev` |
| 7 string | `mxzg-web-1001` |

账号不是正整数时，字段 2 不写，并在 GameLog 说明。没有去接平台 OAuth，也不自己编一个 uid。面板上的选服 id 不写入这包：两例的字段 1、字段 3 都不随选服变化。密码不下发。

s2c 1001 包体为空：日志里下一步才是创角。有包体时字段 1 是角色 id（例如 1000002），字段 2 是毫秒时间，字段 4 见过 28800。

创角 c2s **1002**（这是线上创角，不是占位表里的心跳 1002）：

| 字段 | 日志里的值 |
|------|------------|
| 1 string | 角色名。两例都是「见习冒险家」，这里用面板上写的名字 |
| 2 varint | 0 |
| 3 varint | 2 |
| 4 string | `local` |
| 5 string | `mxzg-web-1001` |

s2c 1002 字段 1 是新角色 id。日志里创角成功后会再发一次 1001。这里照做。

## 顶栏对过的字段（net-20261020 × Role.proto）

字段号以 Role.proto 的 `GResRoleInfo`（cmd **2001**）为准。三份登录都对过：先在线的 `c3bfce22`，uid 111 创出角色 1000002 的 `d6108a92`，uid 960011 创出角色 1000003 的 `5d7c0ba6`。主动推送里没有角色名。旧客户端会发空的 c2s **2001**，s2c 2001 才带这份资料。本客户端进主城后也只发这一帧，不发 51001、11005 那一长串。

对照的是 `d6108a92` 在 `2026-10-20T10:55:07.696` 的 s2c 2001，包体 100 字节。另两例字段 1、2、5、6、9、16 相同；先登录的 `c3bfce22` 包体 102 字节，多了字段 15。这一包开头是：

`08 00 10 00 20 00 28 e8 07 30 01 38 00 40 8c fc d2 c3 01 4a 0f e8 a7 81 e4 b9 a0 e5 86 92 e9 99 a9 e5 ae b6 50 8b b0 db d6 06 58 00 60 8b b0 db d6 06 68 00 70 00 80 01 af e4 d7 d6 06 …`

| 字节 | 字段 | 解开的值 | 顶栏 |
|------|------|----------|------|
| `08 00` | 1 varint，`gem` 宝石 | 0 | **钻石 0**。0 是包里的 0，不是缺字段 |
| `10 00` | 2 varint，`gold` 金币 | 0 | **金币 0** |
| `28 e8 07` | 5 varint，`cup` 奖杯 | 1000 | 不写。不是金币 |
| `30 01` | 6 varint，`level` 等级 | 1 | **Lv1**。回包没到之前不显示占位 Lv1 |
| `4a 0f` + `e8 a7 81 e4 b9 a0 e5 86 92 e9 99 a9 e5 ae b6` | 9 string，`nick` 昵称 | 见习冒险家 | **角色名**。等于这两次 c2s 1002 字段 1。s2c 11005 把同一串字和角色 id 放在一起 |
| `80 01 af e4 d7 d6 06` | 16 varint，`server_create_time` | 1792406063（2026-10-19 10:34:23 UTC） | 不开服天，见下 |
| c2s 2001 整帧 `04 00 00 00 d1 07 00 00` | 空体 | 三例都在对应的 s2c 2001 前面 | 发送 |

三例的字段 1、2、5、6、9、16 都是上面这些数。`c3bfce22` 多一个字段 15 varint = 100（`78 64`），两份新号没有这个字段。不读字段 15，也不把它当成钻石。

开服天仍是「未同步」。字段 16 是开服 unix 秒，不是天数。`docs/day60-open-server.md` 的 `getOpenDays()` 要「当前时间 − 开服当日 0 点」。这一包没有时区，样本也不是 0 点（按登录回包里见过的 +28800 算，是当天 18:34:23）。Mock 的开服天是通关推出来的 `1 + floor(已通关 / 5)`。s2c 3007 的 idx 不是这个天数，拿那个助手会编出一天。所以不写 `Session.openDay`，顶栏第二行仍是「真服 · 角色 id」，主城说明里开服天保持未同步。

| 包 | 日志里看到的 | 顶栏 |
|----|----------------|------|
| s2c 28000 / 25001 / 50000 | 100100 起的活动 id，50000 里还有 `item_type` 奖励 JSON。三份号的形状一样 | 不当成钱包 |
| s2c 21013 / 23000 | 旗标或一份两份新号相同的数字。老号在这段窗口里没有 23000 | 不写 |

解不开的 2001（半截、坏 varint、空包）直接忽略。解开了但某个字段没有，只让那个格子保持未同步，其它解开的照写。拆帧循环不因此停。占位 `CmdId.towerView` 仍是 **2001**，只给 Mock 的幻境之塔，和这帧不是一回事。

## 主线按钮对过的字段（net-20261020 × Battle.proto）

字段号以 Battle.proto 的 `GResChapterData`（cmd **3007**）为准。三份登录都对过，和上面 2001 是同一批连接：`c3bfce22`、`d6108a92`、`5d7c0ba6`。旧客户端在空 c2s 2001 和对应的 s2c 2001 之后，于进游戏同步里发空的 c2s **3007**。三例都夹在 c2s 58017 和 c2s 3004 中间，整帧都是 `04 00 00 00 bf 0b 00 00`。本客户端在进主城、空 c2s 2001 之后马上发这一帧，不等 s2c 2001，也不发夹在中间的 51001、11005、58017，也不发后面的 3004 / 3010 / 3012。3002 在日志里是更晚的操作，这一轮不发。

| 连接 | c2s 3007 | s2c 3007 包体 |
|------|----------|----------------|
| `c3bfce22` | 2026-10-20T00:00:11.772 | `08 f7 96 d8 d6 06 18 00`（00:00:11.775） |
| `d6108a92` | 2026-10-20T10:55:08.073 | `08 d0 af db d6 06 18 00`（10:55:08.164，和别的回包粘在一起） |
| `5d7c0ba6` | 2026-10-20T11:26:42.365 | `08 b6 be db d6 06 18 00`（11:26:42.423） |

| 字节 | 字段 | 三例解开的值 | 主城按钮 |
|------|------|----------------|----------|
| `08 …` | 1 varint，`res_reward_time` | 1792412535 / 1792464848 / 1792466742 | 不写。这是上次领资源的 unix 秒 |
| （没有 `10`） | 2 varint，`now_idx` | 三例都没有这个字段 | 不写成 0。按钮上不出现「当前」 |
| `18 00` | 3 varint，`max_idx` | 0 | **最高 0**。0 是包里的 0 |
| （没有） | 4 repeated，`extra_reward_id` | 三例都没有 | 不读 |

所以日志这三例的按钮是「主线 · 最高 0」，不是「主线 · 未同步」，也不是 Mock 的「主线 · 第 1 关」。`Session.stageId` 仍是进主城时的占位 1，不拿来画按钮，也不拿来发 `stage.enter`。点这颗按钮仍 Toast，不打开 Mock 关卡列表。

两个 idx 都有的包（日志里没有这种样本）写成「主线 · 当前 N / 最高 M」。只有字段 2 时写成「主线 · 当前 N」。都没有时保持「主线 · 未同步」。后到的包只改自己带的那一个 idx，不把另一个清掉。

解不开的 3007（半截、坏 varint、空包）直接忽略，按钮保持上一次。拆帧循环不因此停。占位表里没有 3007。Mock 的 `stage.enter` 仍是 **1201**。

再往后那一长串（51001、11005，以及倩本机登录后的 28000、50000 等）仍只记 `wire.<cmdId>`。不把 Mock 钱包填进去。3007 是这一长串里这一轮唯一多发的一帧。

占位 `CmdId.heartbeat` 仍是 **1002**，只给 Mock。线上心跳是 **1004**。不要把占位表改成 1004，否则和线上创角号撞在一起。

uid 960011 那一帧的包体和 `encodeObservedLoginBody` 字节相同。uid 111 那一帧字段号和值相同，字段顺序不同；两例在旧日志里都拿到了 s2c 1001。编码器跟 960011 的顺序走。TCP 复现用的是日志里 uid 111 的原始字节，不是重新编码的那一版。没有接平台 OAuth。

## 这一步做了什么

- D2 勾选依据是倩本机：桥 13111 上 `收到 s2c 1001`（角色 1000002）以及后面的真服推送。
- 有角色 id 时走和 Mock 相同的 `Main` 场景。空的 c2s 2001 拉角色资料。s2c 2001 的字段 9、6、2、1 写到顶栏的名字、等级、金币、钻石。缺字段仍是未同步。字段 5 不进金币。开服天仍是未同步。
- 紧接着发空的 c2s 3007。s2c 3007 的字段 2、字段 3 写到主城「主线」按钮（当前 idx / 最高 idx）。日志三例没有字段 2、字段 3 是 0，按钮是「主线 · 最高 0」。不写 `Session.stageId`，不打开 Mock 关卡页。不发 3002 / 3004 / 3010。
- 登录后的未知 s2c 继续按长度前缀拆开并记日志。一条处理失败不会丢掉同一包里后面的帧。2001 或 3007 解不开只记一行，顶栏或主线按钮保持上一次。
- `scripts/start-local-all.bat`：先游戏服，再桥。9902 或 13111 已在听则跳过。`stop-local-all.bat` 只停桥。
- 帧编码仍是长度前缀。默认仍是 Mock。玩法协议还没接到真服，D3 全量项不勾。

全量真实协议同步仍是 D3 剩下的部分。
