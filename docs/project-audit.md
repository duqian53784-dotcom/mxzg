# mxzg 当前工程问题与处理顺序

> 历史记录：客户端当前标准以 [architecture.md](architecture.md) 和 [背包标准模块样板](bag-mvc-maintenance.md) 为准。背包已迁入 features/Bag，采用完整名称、BaseModel/BaseController 和单一全局 EventDispatcher；下方旧目录/开关/分层不再作为现行要求。指定核心流程的正式服视觉、交互和规则对照目标继续有效。

2026-10-29，依据当前工作区与日服源码。当前已有资源、协议解码、界面框架与部分真实链路，尚无三端商业发行的完整证据。产品定位已确认为现代化重做版：按新需求评估这些成果的复用价值，重新设计架构与体验；不以旧项目结构、全系统覆盖或像素级复刻为目标。

## 重做定位带来的优先级修正

本审计记录的是现存迁移工程的问题，并不要求逐项修好后才能开始重做。优先交付新架构下的一条可运行玩法切片，验证引擎、三端能力、体验与服务端契约，再将可用成果接入。现有框架、Java 服务端和协议均接受质量与成本评估。

旧页面坐标、旧回退路径和历史快照检查属于旧实现基线。新设计有意改变体验时，应明确更新验收依据并淘汰对应旧断言；不能为了历史测试通过继续复制过时布局。没有设计依据的行为变化仍属于待排查问题。

## 事实基线

`python tools/project_audit.py --json` 可复跑静态清单。第一批整理后的结果：

- 234 个运行时 TypeScript 文件，892 条静态相对导入，605 个 Prefab。
- resources 下 21,596 个非 meta 源文件，643,119,087 字节，613.33 MiB。统计包含目录内全部非 meta 文件，不是构建包或首屏下载量。
- WireSession 7,402 行，screenFill 3,424 行，MainApp 2,384 行，Boot 1,412 行；按物理行统计，包含注释和空行。这些文件同时承担多个业务和生命周期，问题在职责集中。
- 当前设计分辨率 640×1280，fitHeight=true、fitWidth=false；历史 720×1280 说明不能作为当前统一基准。

静态导入不覆盖 Prefab/scene UUID、动态路径、配置、工具与外部调用，不能单独用来决定删除。

## 产品与多端缺口

### 开发预览替代了发行设计

`transportSelect.ts` 默认本机桥，`servers.ts` 仍是本机桥、提审和正式占位；浏览器参数读取散布在多个模块，版本下载直接调用 XMLHttpRequest。尚未看到配套的统一渠道服务与完整三端发布记录。

处理：先建立环境配置与平台接口，尽早构建 H5、Android、微信小游戏最小登录样包；iOS 在对应工具链环境验证。引擎支持发布不代表当前业务和 SDK 已适配，不能等所有玩法完成后再首次构建小游戏。

### 页面存在不等于功能完整

`BackpackInfoView.ts` 停用道具使用；`screenFill.ts` 的英雄升级、升星仍有停用或无协议提示；大量 wire 模块及 `pullIdle()` 仅实现读取。

处理：按玩家动作登记功能状态，先完成登录、出阵、主线、结算、挂机领取、基础养成和重登。资源数、页面数、协议数不能当成功能进度。

### 过期文档误导接入判断

旧 `real-data-audit.md` 称环境没有服务端源码。当前日服仓库实际有 Java gameserver，`module/hero/handler/HeroHandler.java` 的 `@CMD(id = CmdCode._4018)` 已实现 `heroUpLevel`。这证明存在可研究的升级协议和处理代码，尚不证明本机运行同一版本，或客户端可直接安全调用。

处理：交叉核对 Java handler、协议定义、Lua 调用和真实回包，将“未接入”“版本不一致”“确实不支持”区分。不能依据旧文档永久停用功能，也不能只看到协议号就发送写操作。

## 架构问题

### 主会话过度集中

WireSession 集中数十系统的静态状态、请求、同步和通知，`pullIdle()` 还读取邮件、英雄、活动和高级系统。其职责已远超挂机，首登同步与非核心功能绑定。部分查询还可能触发服务端初始化，不能将全量读取视为无代价操作。

处理：保留传输和帧处理，拆登录同步协调器与各 feature 的 service/store；首登只同步主循环所需数据，其他功能进入时加载。不能只是机械拆文件后继续共享全部静态状态。

### 页面双轨长期并存

MainApp 同时调度新 features View 与旧 pagePrefabShell/screenFill；bag、hero、battle、city 的 old 参数保留回退实现。修复可能只覆盖一路，生命周期、布局与按钮绑定继续分叉。

处理：逐页验收新路径，随后删除对应旧分支和开关。未迁页面仍依赖旧层时保留，不能删除整个 ui。

### 基础层反向依赖界面

整理前，UIManager 依赖旧 UI 下的加载器和日志；英雄业务依赖旧 UI 下的出阵状态；背包业务依赖挂机对白文本清理；战报业务依赖挂机 UI 的 Spine 选择。

本批已迁移打开日志到 `framework/ui/UIOpenLog.ts`，出阵状态到 `module/mainline/localLineup.ts`，保留 UUID。剩余三条已登记债务：

- UIManager → ui/prefabLoad：先拆通用加载与业务 UUID 目录。
- bagBoard → ui/idleHangTalkPlan：提取共享文本清理规则。
- battleFromStore → ui/idleHangRoster：分离战斗表现模型与挂机布局。

`tools/architecture-baseline.json` 只记录现存债务；检查拒绝新增反向依赖，也要求移除已解决例外。

### 状态所有权不清

Session、GameStore、WireSession 各保留角色或业务快照；页面还读取本局阵容。Mock 由 NetClient 默认构造及导出引用，测试支持尚未完全脱离生产依赖图。

处理：为每类数据确定唯一 store，Service 处理回包后提交，View 订阅。旧接口过渡期做代理，避免长期双写。Mock 最终只从测试/开发组合根装配。

## 平台与发行问题

### 连接与身份仍面向本机

`ws://127.0.0.1:13111/game` 和 PowerShell TCP 桥验证的是本机链路；数字账号或派生 uid 不能替代渠道鉴权。

处理：生产网关、环境配置、会话票据独立定义，验证 WSS、重连和会话刷新。既有 Java 协议可先保留，没有依据要求同时全面重写服务端。

### 资源与更新缺少交付策略

resources 约 613.33 MiB 源文件，ConfigLoader 按 manifest 读取整批配置。clientVersion 在浏览器跳过远程校验；原生路径的 downloadWithProgress 只是下载字节，未完成更新安装、完整性校验和回滚。

处理：规划启动、核心、战斗与扩展 Bundle；先分析依赖和构建输出，再迁资源路径并保留 UUID。分别制定 H5、App、小游戏更新策略，避免共享依赖被多包重复收集。

### 调试能力没有发行边界

GmHotkey 绑定 F9/反引号，页面还有长按和参数入口。服务端另有执行开关，不能据此断言线上可被利用；但客户端缺少明确的 production 裁剪边界。

处理：调试能力按构建环境注入，服务端独立鉴权与限制；生产包检查入口、脚本和资源，不能只藏按钮。

## 验证与文档问题

已有检查有价值，但 skeleton-check 接近三万行，混合 Mock、协议、UI、源字符串与资产断言。字符串断言阻碍合理重构，引擎 shim 不能证明真实渲染与 SDK 正常。

第一批统一检查为 5/7 通过：架构、脚本绑定、英雄、主城、战斗通过；背包第一格位置断言、旧综合检查背包布局断言失败。两项都已使用迁移前的 TypeScript 复现相同错误，综合检查也在修改前直接失败。这是现存工程的已知基线；保留旧页面时需确认其布局，新设计替换时按新验收依据更新或淘汰相关断言，不把旧坐标当作重做版的强制目标。

纯逻辑、协议契约、View 生命周期、脚本绑定、真实服务端持久化、发布包烟测与固定状态视觉对照应分别维护。persist-roundtrip 使用 JSON 对照库，不能代替真实 MySQL 验收。

本轮没有启动 Creator、连接数据库或完成三端构建和真机验证。5/7 仅是无引擎检查结果，不是功能通过率或上线进度百分比。

## 整理与删除边界

保留已迁美术和稳定 UUID、可用协议规则、运行中页面、新 View 框架与仍被测试引用的 Mock；日服仓库只读参考。

逐页淘汰被新 View 完整替代的旧填充分支、回退开关、重复节点构建及其专用常量。删除前同时核对 TS、Prefab/scene UUID、动态路径、配置、工具与测试，删除后验证玩家路径。无 import 不等于无引用，当前没有证据支持整目录清空 ui、module、Mock 或大批 Prefab。

执行见[重整路线](restructuring-plan.md)，产品基线见[核心需求](product-requirements.md)。历史批次文档保留证据，过期结论以源码和验证修正。
