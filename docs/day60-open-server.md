# 前60天内容迁移清单（按开服自然日）

> 口径：**开服自然日** = `ServerParamService.getOpenDays()`  
> 公式：`ceil((当前时间 - 开服当日0点) / 86400)`，开服当天算第1天。  
> 创角天数：登录类（新号七天/30日签到）按**角色登录天数**；其余活动/玩法几乎全是**开服天数**。

---

## 一、结论先说

1. **系统入口（opencondition）几乎不按天数开**，主要按**主线关卡等级**（`condition_type=1`）。  
2. **按自然日切的是活动轮次与部分玩法门槛**（`promotioncontrol.open_server_day` + `system.xlsx` 的 `*_open_day`）。  
3. 做「前60天可玩」时，必须两套一起迁：  
   - **天数轴**：开服 D1–D60 会开的活动与玩法  
   - **等级轴**：这些活动任务/入口依赖的系统（七日目标已要求推到主线约 **70**）

运营类 `open_server_day=9999` 的活动（竞技之巅、酒馆达标、合成觉醒、诸神之战、狂欢时刻）视为**运营后台开启**，不进默认60天包。

| **D8** | 速战之王、冒险笔记、通行证(需Lv10)、三日任务、周末锦鲤(需Lv10) | 3–30天 | 有循环 | 通行证可后置；三日任务建议做 |

配套表：

- `promotionnew7daylogin`：新号登录 D1–D7 奖励

- `promotionlimitedsetday`：限时礼包按开服日分段（D1–D3 单独档，D4 起统一）

## 四、等级轴：活动依赖的系统（仍要迁）

### 4.1 七日目标直接引用的系统（必保）

`main_battle`、`main_summon`、`main_hero`、`main_hero_make`、`main_pub_task`、`main_pvp`、`main_fantasy_tower`、`main_mission`、`main_blessingpool`、`main_smith_shop`、`main_clan`、`main_fetter`、`main_prophet_tree`、`main_proving_lang`、`main_infinite`、`act_recharge`

任务最高主线目标约 **70** → 主线战斗与挂机至少要做到能推到 70，否则七日目标残缺。

### 4.2 open=1 且建议纳入「60天体验」的等级解锁

| 主线等级 | 系统 |
|---------|------|
| 1 | 召唤、创造法阵、羁绊、圣物/精灵背包 |
| 5 | 铁匠铺 |
| 8 | 竞技场 |
| 10 | 许愿池（低级） |
| 12 | 咖啡馆 |
| 15–18 | 日常副本（金/经验/英雄）、幻境之塔、公会、排行、跨服时空入口 |
| 20 | 祭坛、先知之树 |
| 22 | 羁绊副本 |
| 30 | 高级许愿池、勇者试炼 |
| 32 | 时光神殿-置换 |
| 50 | 月神庇护所、远古战场 |

### 4.3 明确超出常规前60天的（世界等级门槛高）

神装系（个人70+世界65）、组队竞技场（85/75）、讨伐团（105/80）——**默认不进60天包**。

## 六、和新前端引擎的关系

- 活动日历与入口状态机：**按开服日 + 轮次**驱动（对齐 `promotioncontrol`）。  
- 系统红点/入口：**按主线等级 + 少量世界等级**（对齐 `opencondition`）。  
- 一个月「可玩」建议对齐 **P0+部分P1**（D1–D14 体验完整），不必硬凑满60天全部活动。  
- 「迁前60天内容」= **P0–P3 清单**，不是把全量 Lua/ccbi 搬完。
